# Peer-review: взаимооценка вклада в команде

**Дисциплина:** Прогнозирование временных рядов: от статистики до MLOps  
**Вес:** 6 % итоговой оценки + корректирующий коэффициент к PRC  
**Когда:** после финальной защиты MVP (PRC), до публикации итоговых баллов

---

## 1. Назначение

Peer-review дополняет оценку **командного** проекта (29 %) учётом **индивидуального вклада** каждого участника. Студенты оценивают друг друга **анонимно**; преподаватель агрегирует результаты и при необходимости корректирует оценку за PRC.

---

## 2. Механизм

| Элемент | Значение |
|---------|----------|
| Кто оценивает | Каждый член команды оценивает **всех остальных** (не себя) |
| Анонимность | Форма без имён оценивающего; ID студента только для LMS |
| Шкала | 0–100 по каждому критерию |
| Коэффициент $k_{peer}$ | **0,7 – 1,3** — множитель к **командной** оценке PRC |
| Личный балл peer-review | **6 %** × (средний балл от команды / 100) |

### Формула

$$\text{Балл}_{PRC\_итог} = \text{Балл}_{PRC\_командный} \times k_{peer}$$

$$k_{peer} = \text{clip}\left(\frac{\text{средняя оценка студента от peers}}{80}, 0{,}7, 1{,}3\right)$$

где 80 — норматив «полностью выполненный вклад» (уровень «Средний»).

---

## 3. Критерии оценки (для каждого коллеги)

| Критерий | Вес | Что оценивать |
|----------|-----|---------------|
| **Ролевые задачи** | 25 % | Выполнение зоны ответственности (Data / ML / MLOps / Lead) |
| **Качество артефактов** | 25 % | Код, ноутбуки, документация, проходящие CI |
| **Вовлечённость** | 25 % | Участие в встречах, code review, ответы на защитах milestones |
| **Соблюдение дедлайнов** | 25 % | Своевременная сдача milestone и COP |

## 4. Анкета (шаблон для LMS / Google Forms)

### Блок A. Мета

- Название команды: ___
- Ваша роль: Team Lead / Data / ML / MLOps
- Оцениваемый участник (ФИО или ID): ___ *(не себя)*

### Блок B. Оценки (0–100)

| № | Утверждение | 0–100 |
|---|-------------|-------|
| 1 | Выполнил(а) задачи своей роли в milestone ЛР | |
| 2 | Качество его/её commits / модулей достаточное для проекта | |
| 3 | Регулярно участвовал(а) в sync и помогал(а) команде | |
| 4 | Сдавал(а) части работы в срок | |

### Блок C. Открытый вопрос (опционально)

- Один конкретный вклад коллеги: ___
- Одна рекомендация: ___

---

## 5. Правила для студентов

1. Оценивайте **факты** (commits, разделы отчёта, demo), а не личные симпатии.
2. Завышение/занижение без обоснования — основание для пересмотра преподавателем.
3. Если участник **не вносил вклад** — допустима оценка < 40 по критериям.
4. Peer-review **обязателен** для зачёта (см. [grading.md](../docs/grading.md)).

---

## 6. Действия преподавателя

1. После PRC открыть форму на 48–72 ч.
2. Проверить: каждый оценил **n−1** коллег.
3. Вычислить средние; выявить выбросы (разброс > 40 без комментария).
4. При конфликте — короткое интервью + git log.
5. Применить $k_{peer}$; опубликовать **только итог**, не сырые анкеты.

### Красные флаги

| Ситуация | Действие |
|----------|----------|
| Все оценили одного на 100 / 0 | Проверка collusion |
| 0 commits при оценке «80+» | Снижение $k_{peer}$ |
| Жалоба на free-rider | Сверка с [milestone rubrics](rubrics.md) |

---

## 7. Пример расчёта

| Студент | Средняя от peers | $k_{peer}$ | PRC командный 80 % | PRC итог |
|---------|------------------|------------|---------------------|----------|
| A | 88 | 1,10 | 23,2 / 29 | 25,5 / 29 |
| B | 72 | 0,90 | 23,2 / 29 | 20,9 / 29 |
| C | 45 | 0,70 | 23,2 / 29 | 16,2 / 29 |

*PRC командный 80 % = 23,2 балла из 29.*

# Критерии оценки проектной работы

**Формат:** командный PRC, 3–4 человека  
**Шкала уровней:** Базовый (60 %) · Средний (80 %) · Продвинутый (100 %)

Оценка выставляется **команде** с возможностью дифференциации по индивидуальному вкладу (см. [instructor_guide.md](instructor_guide.md)).

---

## 1. Сводная матрица

| Критерий | Вес | Базовый | Средний | Продвинутый |
|----------|-----|---------|---------|-------------|
| **A. Постановка и работа с партнёром** | 15 % | Задача описана, был kick-off | Письменный устав, ≥2 итерации с партнёром | Партнёр участвовал в приёмке MVP, метрики согласованы |
| **B. Данные и EDA** | 15 % | Данные получены, базовый EDA | Предобработка документирована, ACF/сезонность | Качество данных обосновано, ограничения и риски описаны |
| **C. Моделирование** | 25 % | Baseline + 1 модель, метрики на test | ≥3 подхода, walk-forward/chrono split | Обоснованный выбор, диагностика, business-метрика |
| **D. MVP и деплой** | 25 % | API + прогноз локально | Docker, `/health` + `/predict`, DEPLOY.md | CI, тесты, demo без ручных фиксов |
| **E. Мониторинг и устойчивость** | 10 % | Устно описан drift | Черновик monitoring.md, симуляция drift | PSI/MAE monitoring, plan retraining |
| **F. Защита и документация** | 10 % | Презентация + README | Отчёт 15+ стр., все говорят | Сильная demo, roadmap post-MVP |

## 2. Детализация по уровням

### A. Постановка и работа с партнёром

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | Названа цель прогноза, указан партнёр или proxy-кейс, горизонт определён |
| **Средний** | [Устав](templates/project_charter.md) заполнен, зафиксированы метрика успеха и ограничения данных, есть протокол ≥1 встречи |
| **Продвинутый** | Партнёр подтвердил релевантность MVP; команда скорректировала scope по feedback; roadmap согласован |

### B. Данные и EDA

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | `data/raw` + описание; график ряда; пропуски учтены |
| **Средний** | `data/processed`, seasonal/ACF анализ, preprocessing_meta, Milestone 1 сдан в срок |
| **Продвинутый** | Сопоставление с доменными событиями, обоснованный выбор $s$ и методов imputation, воспроизводимый pipeline |

### C. Моделирование

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | Naive/ES baseline; одна рабочая модель (ARIMA / ML / LSTM); MAE или RMSE на test |
| **Средний** | ≥3 модели в одной таблице; хронологический split; протокол в `docs/validation.md`; модель сохранена |
| **Продвинутый** | Walk-forward; HPO документирован; выбор модели с учётом интерпретируемости и SLA партнёра; нет утечек |

### D. MVP и деплой

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | Скрипт или API возвращает прогноз; инструкция запуска |
| **Средний** | FastAPI/Flask, Docker build успешен, валидация входа, demo на защите |
| **Продвинутый** | docker-compose, CI pipeline green, pytest ≥2 теста, версионирование модели |

### E. Мониторинг и устойчивость

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | В отчёте различены data/concept drift, названы риски |
| **Средний** | `docs/monitoring.md`: метрики, пороги; симуляция ≥1 сценария деградации |
| **Продвинутый** | PSI/KS или rolling MAE; сценарий retraining; задание «Сломай модель» или A/B план |

### F. Защита и документация

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | Презентация 10+ слайдов; README с quick start; все участники присутствуют |
| **Средний** | Итоговый PDF-отчёт; live demo; ответы на вопросы по своим ролям |
| **Продвинутый** | Качество pilot для партнёра; чёткий roadmap; репозиторий готов к handover |

## 3. Milestone-рубрики (ЛР1–8, вариант A)

Каждая ЛР оценивается **отдельно** (5 % дисциплины). Уровни Б/С/П — см. [grading.md](../docs/grading.md).

| ЛР | Ответственная роль | Б (60 %) | С (80 %) | П (100 %) |
|----|-------------------|----------|----------|-----------|
| **ЛР1** EDA | Data | Данные + график ряда | + ACF/PACF, сезонность | + предметные выводы, воспроизводимость |
| **ЛР2** Preprocessing | Data | `processed/`, базовая очистка | + STL, ADF/KPSS | + pipeline в `src/preprocessing.py` |
| **ЛР3** Statistical | ML | Baseline + 1 stat model | + диагностика остатков | + обоснованный порядок ARIMA |
| **ЛР4** ML | ML | 1 ML-модель, метрики | + лаги/exog, сравнение с ЛР3 | + feature pipeline |
| **ЛР5** Neural | ML | LSTM/GRU обучается | + сравнение с ЛР3–4 | + стабильный training pipeline |
| **ЛР6** Validation | ML | Walk-forward / split | + HPO, `best_model` | + Optuna, нет утечек |
| **ЛР7** Drift | ML + MLOps | Описан drift | + `monitoring.md`, симуляция | + PSI/MAE, plan retraining |
| **ЛР8** Deploy | MLOps | API локально | + Docker + `DEPLOY.md` | + CI green, pytest |

**PRC (30 %)** — сводная rubric §1 (критерии A–F). **Не дублирует** сумму ЛР; оценивает **целостность MVP** на защите.

---

## 4. Индивидуальный вклад

Каждый участник должен:

- [ ] Иметь ≥ 5 содержательных commits в репозитории **или** эквивалентный вклад (ноутбук, модуль), зафиксированный в README;
- [ ] Выступить на защите (≥ 2 слайда / ≥ 2 мин);
- [ ] Ответить на вопрос по своей роли.

**Снижение оценки:** участник не может объяснить код своей зоны; отсутствие на защите без уважительной причины.

---

## 5. Штрафы и бонусы (рекомендация преподавателю)

| Ситуация | Корректировка |
|----------|---------------|
| Срыв deadline milestone > 1 нед | −1 уровень за компонент |
| Нарушение NDA / публикация сырых данных | 0 за проект + дисциплинарно |
| Партнёрская благодарность / pilot | + рассмотреть «Продвинутый» |
| Open-source release (без секретов) | бонус по усмотрению |

---

## 6. Перевод в баллы (пример)

```
Балл команды = Σ (вес_критерия × процент_уровня)

Базовый = 60 %, Средний = 80 %, Продвинутый = 100 %
```

Пример: все критерии на «Среднем» → 0.8 × 100 = **80 баллов** (до дифференциации по вкладу).

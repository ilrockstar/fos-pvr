# Критерии оценки проектной работы

**Формат:** командный PRC, 3–4 человека  
**Шкала уровней:** Базовый (60 %) · Средний (80 %) · Продвинутый (100 %)

$$\text{Балл}_{PRC\_итог} = \text{Балл}_{комиссии} \times k_{peer}$$

Оценка выставляется **команде** с дифференциацией по индивидуальному вкладу ([peer_review.md](peer_review.md)).

---

## 1. Критерии комиссии на защите PRC (100 %)

| Критерий | Вес | Что проверять |
|----------|-----|---------------|
| **A. Полнота функциональности MVP** | 30 % | Модель прогнозирует; REST API стабилен; `docker-compose up` поднимает FastAPI + MLflow; пайплайны автоматизированы |
| **B. Качество кода и архитектура** | 20 % | Нет хардкода; ООП/модули; структура репозитория; читаемые Dockerfile и CI |
| **C. Мониторинг, устойчивость, ретренинг** | 20 % | Реакция на drift (симуляция); описан и показан retraining |
| **D. Презентация и доклад** | 15 % | Графики факт vs прогноз; аргументированные выводы; регламент **10 мин** |
| **E. Техническая документация** | 15 % | README, DEPLOY.md, описание API, инженерный отчёт |

---

## 2. Детализация по уровням (A–E)

### A. Полнота функциональности MVP (30 %)

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | Прогноз получается локально; API отвечает на `/predict` |
| **Средний** | `docker-compose up --build` поднимает FastAPI + MLflow; demo на защите без сбоев |
| **Продвинутый** | Автоматизированы train → register → serve; CI green; end-to-end за ≤ 5 мин |

### B. Качество кода и архитектура (20 %)

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | Код запускается; базовая структура `src/`, `data/` |
| **Средний** | Модули по ролям; нет критичного хардкода; Dockerfile воспроизводим |
| **Продвинутый** | ООП/слои; тесты; единый стиль; репозиторий готов к handover |

### C. Мониторинг, устойчивость, ретренинг (20 %)

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | Описаны drift и retraining в отчёте |
| **Средний** | `docs/monitoring.md`; скрипт симуляции; алерт или отчёт Evidently |
| **Продвинутый** | Демо деградации + восстановления; триггер retrain; связь с [ПЗ5](../M4-infrastructure-and-deployment/pz05_break_the_model.md) |

### D. Презентация и доклад (15 %)

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | 10+ слайдов; все участники присутствуют |
| **Средний** | Графики факт vs прогноз; доклад **10 мин**; ответы по ролям |
| **Продвинутый** | Сильная бизнес-история; обоснование метрик (MAE/MAPE/quantile); уложились в регламент |

### E. Техническая документация (15 %)

| Уровень | Дескриптор |
|---------|------------|
| **Базовый** | README с quick start |
| **Средний** | DEPLOY.md, описание API; инженерный отчёт 15+ стр. |
| **Продвинутый** | Таблица экспериментов; схема MLOps; [устав](templates/project_charter.md) и протоколы партнёра |

## 3. Milestone-рубрики (ЛР1–10)

Каждая ЛР оценивается **отдельно** (4 % дисциплины). Уровни Б/С/П — см. [grading.md](../docs/grading.md).

| ЛР | Ответственная роль | Б (60 %) | С (80 %) | П (100 %) |
|----|-------------------|----------|----------|-----------|
| **ЛР1** EDA | Data Analyst | Данные + график ряда | + ACF/PACF, сезонность | + предметные выводы, воспроизводимость |
| **ЛР2** Preprocessing | Data Analyst | `processed/`, базовая очистка | + STL, ADF/KPSS | + pipeline в `src/preprocessing.py` |
| **ЛР3** Statistical | ML Engineer | Baseline + 1 stat model | + SARIMA/ES, ACF/PACF | + обоснованный начальный порядок |
| **ЛР4** Stat diagnostics | ML Researcher | Подбор параметров | + AIC/BIC, диагностика остатков | + финальная SARIMA зафиксирована |
| **ЛР5** Regression | ML Engineer | Linear/Ridge | + лаги/exog, сравнение с ЛР4 | + feature table для ЛР6 |
| **ЛР6** ML | ML Engineer | 1 ML-модель | + RF/XGBoost, vs stat | + feature pipeline |
| **ЛР7** Neural | ML Engineer | LSTM/GRU обучается | + сравнение с ЛР3–6 | + стабильный training pipeline |
| **ЛР8** Validation / drift | ML Researcher + MLOps | Walk-forward / split | + HPO, `best_model`, drift rules | + Optuna, PSI, plan retraining |
| **ЛР9** Deploy | MLOps | API + Docker + MLflow | + `docker-compose`, CI | + demo без правок |
| **ЛР10** Monitoring | MLOps + ML Researcher | drift-report + playbook | + Evidently, simulate_drift | + auto-retrain в пайплайне |

**PRC (35 %)** — сводная rubric §1 (критерии A–E). **Не дублирует** сумму ЛР; оценивает **целостность MVP** на защите. Индивидуальная дифференциация — через \(k_{peer}\) из [peer_review.md](peer_review.md).

---

## 4. Индивидуальный вклад

Каждый участник должен:

- [ ] Иметь ≥ 5 содержательных commits в репозитории **или** эквивалентный вклад (ноутбук, модуль), зафиксированный в README;
- [ ] Выступить на защите (≥ 2 слайда / ≥ 2 мин);
- [ ] Ответить на вопрос по своей роли.

**Снижение оценки:** участник не может объяснить код своей зоны; отсутствие на защите без уважительной причины.

---

## 5. Штрафы и бонусы (рекомендация преподавателю)

| Ситуация | Корректировка |
|----------|---------------|
| Срыв deadline milestone > 1 нед | −1 уровень за компонент |
| Нарушение NDA / публикация сырых данных | 0 за проект + дисциплинарно |
| Партнёрская благодарность / pilot | + рассмотреть «Продвинутый» |
| Open-source release (без секретов) | бонус по усмотрению |

---

## 6. Перевод в баллы (пример)

```
Балл команды = Σ (вес_критерия × процент_уровня)

Базовый = 60 %, Средний = 80 %, Продвинутый = 100 %
```

Пример: все критерии на «Среднем» → 0.8 × 100 = **80 баллов** (до дифференциации по вкладу).

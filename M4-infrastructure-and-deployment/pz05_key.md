# Ключ ПЗ5 «Сломай модель» (преподавателю)

**Max:** 100 баллов → **2 %** дисциплины.  
**Срок:** 2 недели, параллельно ЛР10.

---

## Шкала по критериям

| № | Критерий | Max | Что проверять |
|---|----------|-----|---------------|
| 1 | ≥ 3 сценария дрейфа | 15 | Разные типы (shift / noise / season / spike / trend); функции в `scripts/apply_drift_<фамилия>.py` |
| 2 | Реалистичный сценарий ≥ 25 % | 15 | Деградация MAE или RMSE ≥ 25 %; бизнес-обоснование выбора |
| 3 | Таблица деградации | 15 | Baseline + все сценарии; формула degradation % корректна |
| 4 | Стратегия ретренинга | 20 | Описаны триггер, окно данных, шаги переобучения; есть код или воспроизводимый протокол |
| 5 | Восстановление качества | 20 | Метрики после retrain существенно лучше, чем на drift; до/после в отчёте |
| 6 | Код и документация | 15 | Читаемый скрипт, README/комментарии, воспроизводимость (seed, пути) |

### Начисление по критериям

| Критерий | 0 % | 50 % | 100 % критерия |
|----------|-----|------|----------------|
| 1 | < 3 сценариев | 3 сценария, слабое различие | ≥ 3 осмысленных, разных сценария |
| 2 | < 25 % или нет обоснования | ≥ 25 %, слабое обоснование | ≥ 25 % + правдоподобный кейс |
| 3 | Нет таблицы | Таблица без baseline | Полная таблица MAE/RMSE/degradation |
| 4 | Только текст «переобучим» | План без реализации | Реализованный retrain + пороги |
| 5 | Нет сравнения | Частичное улучшение | Явное восстановление к baseline |
| 6 | Код не запускается | Запускается, мало комментариев | Чистый, документированный код |

## Уровни (для быстрой проверки)

| Уровень | Баллы | Признаки |
|---------|-------|----------|
| **Базовый (60)** | 60–69 | ≥ 3 сценария; один ≥ 25 %; таблица; идея retrain без полного восстановления |
| **Средний (80)** | 70–89 | + реализован retrain; метрики улучшились; пороги мониторинга |
| **Продвинутый (100)** | 90–100 | + связь с дашбордом ЛР10; гибридная/триггерная стратегия; откат при ухудшении; корректно data vs concept drift |

---

## Чек-лист приёмки

### Обязательно (минимум зачёта по ПЗ5)

- [ ] Модель из проекта, зафиксирован baseline (MAE / RMSE)
- [ ] ≥ 3 сценария в коде
- [ ] Таблица деградации
- [ ] Один сценарий ≥ 25 %
- [ ] Описана стратегия retrain (хотя бы текстом)

### Для 80+

- [ ] Скрипт retrain или ноутбук с воспроизводимым пайплайном
- [ ] Метрики **после** retrain лучше, чем на drift-данных
- [ ] Порог срабатывания (например, MAE +25 % за 7 дней) и окно данных (например, 90 дней)

### Для 90–100

- [ ] Алерт / скриншот дашборда команды (ЛР10)
- [ ] План отката, если новая модель хуже
- [ ] Корректная терминология: data drift vs concept drift
- [ ] Сценарий включён или предложен для `docs/monitoring.md`

## Эталонные ожидания по сценариям

| Сценарий | Типичная деградация | Тип drift |
|----------|---------------------|-----------|
| Mean shift × 1.3–1.5 | 25–60 % MAE | Data drift |
| Noise σ = 5–15 % от std | 15–40 % | Data drift |
| Sudden spike × 2 на 10–20 точек | 20–50 % | Data drift / аномалия |
| Seasonal shift 7 дней | 10–35 % | Data drift |
| Trend + linspace | 25–45 % | Data / concept (зависит от модели) |

> Допустимо, если один сценарий < 25 %, но **выбранный** «победитель» ≥ 25 %.

---

## Типичные ошибки (−баллы)

| Ошибка | Рекомендация |
|--------|--------------|
| Три сценария — вариации одного mean shift | Требовать разные **типы** искажения |
| Деградация на train, не на test/hold-out | Считать метрики на отложенной выборке |
| «Переобучаем раз в месяц» без триггера | Нет баллов по критерию 4 |
| Retrain на тех же данных без drift | Нет восстановления на «сломанных» данных |
| Путают data и concept drift | Комментарий в отчёте; −5…10 к критерию 6 |
| Скрипт с hardcoded путями без README | −5 к критерию 6 |

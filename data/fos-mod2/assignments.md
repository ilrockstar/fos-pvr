# Тема 1. Подбор параметров и диагностика моделей

## Задание 1. Устный коллоквиум: «Читаем ACF и PACF»

**Типаж:** Устный экзамен / коллоквиум с уточняющими вопросами  
**Данные:** Графики ACF/PACF для 2–3 рядов (преподаватель показывает заранее или строит на Air Passengers / цене нефти Brent)

**Задание:**  
Студент получает графики ACF и PACF для неизвестного ряда. За 10 минут готовит устный ответ: какой порядок AR/MA предположить и почему. Затем 15–20 минут — диалог с преподавателем (уточняющие вопросы «на лету»).

**Примерные вопросы преподавателя:**

- Почему вы выбрали именно p=1, а не p=2?
- Что означает резкий обрыв PACF после лага 2?
- Как бы вы изменили вывод, если бы ряд был нестационарным?


| Уровень         | Критерии                                                                                                                                       |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Базовый**     | Верно определяет тип обрыва (AR или MA), называет примерный порядок (±1)                                                                       |
| **Средний**     | Обосновывает выбор ссылкой на конкретные лаги, упоминает необходимость проверки стационарности                                                 |
| **Продвинутый** | Различает сезонные и несезонные компоненты ACF, предлагает SARIMA при наличии сезонных пиков, отвечает на все уточняющие вопросы без подсказок |

## Задание 2. Индивидуальный кейс: «Подбор порядка ARIMA»

**Типаж:** Индивидуальный кейс на реальных данных  
**Данные:** [Цена нефти Brent](data_sources.md) (Yahoo Finance / Investing.com) или [курс USD/RUB](data_sources.md) (ЦБ РФ) — месячные данные за 3–5 лет

**Задание:**  

1. Загрузить ряд, построить ACF/PACF.
2. Провести тест стационарности (ADF).
3. Перебрать 3–5 комбинаций (p, d, q) и выбрать лучшую по AIC.
4. Устно (3–5 мин) объяснить, почему выбрана именно эта модель.


| Уровень         | Критерии                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------- |
| **Базовый**     | Ряд загружен, построены ACF/PACF, выбрана хотя бы одна рабочая ARIMA с обоснованием          |
| **Средний**     | Сравнены ≥3 модели по AIC, проведён ADF-тест, d выбран обоснованно                           |
| **Продвинутый** | Сравнение AIC и BIC, обсуждение компромисса «простота vs точность», прогноз на 3 шага вперёд |

## Задание 3. Дискуссия: «AIC против BIC — что выбрать?»

**Типаж:** Дискуссия / дебаты  
**Формат:** 2 группы по 3–4 человека, 25 мин дискуссия + 5 мин итоги

Группа А защищает AIC как основной критерий выбора модели. Группа Б — BIC. Каждая группа готовит 3 аргумента и 1 контраргумент. Преподаватель задаёт провокационный вопрос: *«У вас 50 наблюдений и ARIMA(5,1,4) выигрывает по AIC. Берём?»*


| Уровень         | Критерии                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Базовый**     | Называет определение AIC/BIC, приводит 1 аргумент за свой критерий                                                         |
| **Средний**     | Объясняет штраф за число параметров, приводит пример, когда критерии расходятся                                            |
| **Продвинутый** | Связывает выбор критерия с размером выборки и целью (прогноз vs объяснение), убедительно отвечает на провокационный вопрос |

## Задание 4. Защита мини-работы: «Остатки говорят правду»

**Типаж:** Защита проекта / работы с вопросами «почему сделано именно так»

3. Провести тест Льюнга-Бокса на автокорреляцию остатков.
4. На защите ответить: «Модель адекватна? Что бы вы улучшили?»


| Уровень         | Критерии                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Базовый**     | Остатки построены, тест проведён, дан ответ «адекватна / нет»                                                              |
| **Средний**     | Интерпретирует все 3 диагностических графика, корректно читает p-value теста                                               |
| **Продвинутый** | Выявляет паттерн в остатках (например, сезонность), предлагает конкретное улучшение модели (SARIMA, добавление регрессора) |

## Задание 7. Индивидуальный кейс: «SARIMA для сезонного ряда»

**Типаж:** Индивидуальный кейс на реальных данных  
**Данные:** [Air Passengers](data_sources.md), [розничные продажи](data_sources.md) (FRED) или самостоятельный ряд с явной сезонностью

3. Сравнить с обычной ARIMA по AIC и визуально на графике прогноза.
4. Кратко (устно или письменно): когда SARIMA оправдана?


| Уровень         | Критерии                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------- |
| **Базовый**     | SARIMA обучена, сезонность определена верно, есть сравнение с ARIMA                               |
| **Средний**     | Перебрано ≥2 варианта SARIMA, прогноз визуализирован, AIC обоснован                               |
| **Продвинутый** | Объясняет роль (P,D,Q,s), обсуждает, достаточно ли экспоненциального сглаживания как альтернативы |

## Задание 8. Индивидуальный кейс: «Конструктор лаговых признаков»

**Типаж:** Индивидуальный кейс на реальных данных  
**Данные:** [Цена золота](data_sources.md) или [индекс IMOEX](data_sources.md) — дневные/недельные данные

**Задание:**  

1. Создать лаги y_{t-1}, y_{t-2}, y_{t-5}, y_{t-10}.
2. Обучить линейную регрессию для прогноза на 1 шаг.
3. Определить, какой лаг наиболее значим.
4. Объяснить, почему нельзя перемешивать данные при train/test split.


| Уровень         | Критерии                                                                          |
| --------------- | --------------------------------------------------------------------------------- |
| **Базовый**     | Лаги созданы корректно, модель обучена, назван самый важный лаг                   |
| **Средний**     | Хронологическое разбиение, метрика MAE/RMSE на тесте, интерпретация коэффициентов |
| **Продвинутый** | Сравнивает 2 набора лагов, обсуждает мультиколлинеарность между соседними лагами  |

## Задание 20. Круглый стол: «Выбор модели — итоговое решение»

**Типаж:** Дискуссия / круглый стол  
**Формат:** 4–6 человек, 30 мин, итог — общая «шпаргалка»

**Кейсы для обсуждения (каждый студент получает 1):**


| №   | Ряд                                  | Условия                    |
| --- | ------------------------------------ | -------------------------- |
| A   | Продажи магазина, 2 года, месячные   | Сезонность, 24 точки       |
| B   | Курс BTC, 3 года, дневные            | 1000+ точек, волатильность |
| C   | Температура в городе, 1 год, дневные | Сильная годовая сезонность |
| D   | Выручка стартапа, 8 месяцев          | Мало данных, тренд         |


**Задача:** Для своего кейса предложить модель (AR/MA/ARMA/ARIMA/SARIMA/ES/линейная/RF/boosting) и аргументировать. Группа составляет общую шпаргалку «Если… → то…».


| Уровень         | Критерии                                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Базовый**     | Предложена подходящая модель для своего кейса                                                                      |
| **Средний**     | Аргументация учитывает размер ряда и сезонность, участие в шпаргалке                                               |
| **Продвинутый** | Предлагает fallback-модель («если данных станет больше → перейти на…»), шпаргалка группы полная и непротиворечивая |

## Приложение: быстрая шпаргалка по моделям


| Модель                 | Когда использовать                                   |
| ---------------------- | ---------------------------------------------------- |
| **AR**                 | PACF обрывается после p, ряд стационарен             |
| **MA**                 | ACF обрывается после q                               |
| **ARMA**               | Комбинация AR и MA, без тренда                       |
| **ARIMA**              | Есть тренд, нужно дифференцирование                  |
| **SARIMA**             | Явная сезонность с известным периодом                |
| **Exp. Smoothing**     | Быстрый прогноз, тренд + сезонность, мало параметров |
| **Линейная регрессия** | Много признаков, нужна интерпретация                 |
| **Random Forest**      | Нелинейности, ≥100 точек, много признаков            |
| **Gradient Boosting**  | Максимальная точность на табличных признаках         |

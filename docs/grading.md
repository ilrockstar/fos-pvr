# Система итогового оценивания

**Дисциплина:** Прогнозирование временных рядов: от статистики до MLOps  
**Архитектура ФОС:** **вариант A** — лабораторные работы как **milestones единого группового проекта** (3–4 человека)  
**Форма промежуточной аттестации:** дифференцированный зачёт

---

## 1. Структура итоговой оценки

| Компонент | Вес | КИМ в репозитории | Примечание |
|-----------|-----|-------------------|------------|
| **Лабораторные работы** (8 milestones) | **40 %** | [M1](../M1-analysis-and-preparation/) … [M4](../M4-infrastructure-and-deployment/) | По **5 %** за каждую ЛР; сдаёт **команда** |
| **Практические задания / квизы** (ПЗ1–ПЗ5) | **10 %** | [ПЗ1–ПЗ5](#2-практические-задания-пз1пз5) | По **2 %** каждое; ПЗ5 — индивидуально |
| **Соревнование (COP)** | **15 %** | [Forecast Cup](../M3-neural-networks/competition.md) | 50 % качество + 50 % отчёт |
| **Командный проект (PRC)** — финальная защита MVP | **30 %** | [Project](../Project/) | См. [rubrics.md](../Project/rubrics.md) |
| **Peer-review** | **5 %** | [peer_review.md](../Project/peer_review.md) | Коэффициент 0,7–1,3 к части PRC |
| **ИТОГО** | **100 %** | | |

> **Экзамен не предусмотрен.** Раздел [Exam/](../Exam/) не используется при варианте A.

## 2. Лабораторные работы (40 %)

Каждая ЛР — **контрольная точка (milestone)** сквозного группового проекта. Отчёт по ЛР = **раздел** общего проектного отчёта; код = **модуль** общего репозитория `team-<name>/`.

| ЛР | Название | Вес | Артефакт в репозитории команды |
|----|----------|-----|--------------------------------|
| ЛР1 | EDA временного ряда | 5 % | `notebooks/01_eda.ipynb`, `docs/report/01_eda.md` |
| ЛР2 | Предобработка и декомпозиция | 5 % | `data/processed/`, `src/preprocessing.py` |
| ЛР3 | Классические статистические модели | 5 % | `src/stat_models.py`, `models/sarima/` |
| ЛР4 | Регрессионные и ML-модели | 5 % | `src/ml_models.py`, `data/features/` |
| ЛР5 | Нейросетевые модели (LSTM/GRU) | 5 % | `src/neural_models.py`, `models/lstm/` |
| ЛР6 | Валидация и подбор гиперпараметров | 5 % | `docs/validation.md`, `models/best_model/` |
| ЛР7 | Анализ устойчивости и дрейфа | 5 % | `src/drift_analysis.py`, `docs/monitoring.md` |
| ЛР8 | Контейнеризация и CI/CD | 5 % | `Dockerfile`, `.github/workflows/`, `DEPLOY.md` |

### Оценивание одной ЛР (шкала 0–100 → в зачёт 5 %)

| Уровень | % от max ЛР | Описание |
|---------|-------------|----------|
| Базовый | 60 | Milestone сдан, минимальные артефакты, есть пробелы |
| Средний | 80 | Полный объём, корректные выводы, код в репозитории команды |
| Продвинутый | 100 | Глубокий анализ, воспроизводимость, готовность к следующему milestone |

**Формула вклада ЛР в итог:**

$$\text{Балл}_{ЛР_i} = \text{Вес}_i \times \frac{\text{Уровень \%}}{100}, \quad \text{Вес}_i = 5\%$$

### Защита milestone

На защите ЛР команда (5–7 мин) показывает **прогресс проекта**, а не изолированную работу. Преподаватель задаёт вопросы по ролям КРМ.

$$\text{Балл}_{ПЗ} = 2\% \times \frac{\text{score}_{0-100}}{100}$$

## 4. Соревнование COP (15 %)

| Компонент | Вес внутри COP | Описание |
|-----------|----------------|----------|
| Качество на private test | 50 % | Primary metric: **SMAPE** (или RMSE — см. [competition/scoring.md](../M3-neural-networks/competition/scoring.md)) |
| Отчёт с описанием подхода | 50 % | Validation, архитектура, воспроизводимость |

**Формат:** команда 2–4 человека (может совпадать с проектной командой).

$$\text{Балл}_{COP} = 15\% \times \left(0{,}5 \cdot \frac{\text{rank score}}{100} + 0{,}5 \cdot \frac{\text{report score}}{100}\right)$$

---

## 5. Командный проект PRC (30 %)

Финальная защита **целостного MVP** (см. [Project/rubrics.md](../Project/rubrics.md)):

| Критерий | Вес внутри PRC |
|----------|----------------|
| Полнота функциональности | 30 % |
| Качество кода / архитектуры | 20 % |
| Мониторинг и ретренинг | 20 % |
| Презентация | 15 % |
| Документация | 15 % |

$$\text{Балл}_{PRC} = 30\% \times \frac{\text{score}_{PRC}}{100} \times k_{peer}$$

где $k_{peer}$ — коэффициент peer-review (0,7–1,3).

---

## 6. Peer-review (5 %)

Анонимная взаимооценка после финальной защиты. См. [Project/peer_review.md](../Project/peer_review.md).

| Балл peer-review | Вклад в итог |
|------------------|--------------|
| 0–100 | **5 %** × (score / 100) |

Коэффициент $k_{peer}$ применяется **дополнительно** к оценке за PRC (не заменяет peer-балл).

---

## 7. Шкала перевода в зачёт (дифференцированный)

| Сумма баллов | Оценка ECTS / зачёт |
|--------------|---------------------|
| ≥ 90 | Отлично (5 / A) |
| 75–89 | Хорошо (4 / B) |
| 60–74 | Удовлетворительно (3 / C) — **зачёт** |
| < 60 | Незачёт |

*Конкретные пороги согласуются с локальными нормативными актами вуза.*

---

## 8. Минимальные пороги (обязательные)

Для допуска к зачёту студент / команда должны:

- [ ] Сдать **≥ 6 из 8** milestones ЛР на уровне не ниже «Базовый» (60 %)
- [ ] Участвовать в **COP** (≥ 1 валидный submission)
- [ ] Защитить **PRC** (MVP demo)
- [ ] Заполнить **peer-review** (≥ 3 анкеты на команду)

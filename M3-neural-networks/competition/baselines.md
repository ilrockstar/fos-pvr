# Forecast Cup — baselines и ориентиры

Организатор публикует эти числа **после старта** соревнования (на public validation slice или на описании задачи). Студенты ориентируются на beat baseline, не на подгонку под private test.

---

## Baseline-модели

| ID | Модель | Описание | Ожидаемый SMAPE* |
|----|--------|----------|------------------|
| B0 | **Naive** | $\hat{y}_t = y_{t-1}$ | ~8–12 % |
| B1 | **Seasonal naive** | $\hat{y}_t = y_{t-7}$ | ~6–10 % |
| B2 | **SARIMA** | $(1,1,1)(1,1,1,7)$ на train | ~5–9 % |
| B3 | **ML (RF)** | Лаги + календарь из ЛР4 | ~5–8 % |

\*Диапазоны ориентировочные для суточной нагрузки; фактические значения считает преподаватель на public slice.

---

## Зачётный порог

| Условие | Порог |
|---------|-------|
| Beat B0 (naive) | SMAPE_private < SMAPE_B0 × 0.95 |
| Зачёт COP | Сабмит валиден + neural + beat B0 |
| Бонус «Boss defeated» | Beat B2 (SARIMA) |

---

## Public vs Private

| Leaderboard | Данные | Назначение |
|-------------|--------|------------|
| **Public** (optional) | Последние 12 дней из 60-day test | Self-check формата, не для подбора |
| **Private** | Все 60 дней test | **Финальный ranking** |

> Подбор гиперпараметров **только** по walk-forward внутри train — не по public LB более 3 итераций подряд (честное правило; контроль — отчёт).

## Рекомендация командам

1. Сначала beat **B1** на local val.
2. Затем neural + early stopping.
3. Сравните **MAE** (МВт·ч) для презентации заказчику — даже при близком SMAPE.
